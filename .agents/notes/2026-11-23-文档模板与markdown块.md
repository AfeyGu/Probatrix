# 文档模板：`markdown()` 块与 docs 目录约定

内置「使用文档」模板把软件目录 `docs/` 里的 Markdown 直接当计算书读：下拉选一篇，右侧预览即该文档，可照样导出 HTML/PDF。为它新增了 `Probatrix.markdown(text)`。

## 关键取舍

- **新增块类型，不改 `p()`**。`p()` 的「永不解析、长得像结构也按字面显示」是既有契约（`tests/test_html_contract.py::test_content_is_never_markup` 锁定），改它等于动所有模板的正文渲染。`markdown()` 是平行入口，两条契约互不干扰。
- **不引第三方 md 库**。便携包内置固定库清单，`markdown-it-py` 只是开发机碰巧装着，不在依赖里。`docs/manual` 实际用到的语法只有标题、围栏代码块、有序/无序列表、管道表格、引用、分隔线、行内代码/粗体/链接，`src/probatrix/md.py` 约 120 行覆盖，并有真实手册做回归（`tests/test_manual_docs.py`）。用不到的语法（setext 标题、深层嵌套、图片、HTML 直通）明确不做。
- **站内 `.md` 链接不生成 `<a>`**。预览区是页面内嵌容器，真链接会把整个界面跳走；渲染成行内代码。http(s) 链接才出 `<a target="_blank" rel="noopener noreferrer">`。
- **文档目录靠「模板文件位置」定位**。从 `examples/` 向上逐级找 `docs/`：便携包命中 `app/docs/`，源码仓库命中 `CalcBook/docs/`；都没有再退到当前工作目录的 `docs/`。扫到什么列什么——放哪些文档进 `docs/` 由 `tools/build_release.py` 决定，模板不甄别。
- **零前端改动**。下拉就是 `Field(choices=...)`，预览就是 `run` 返回的 `html`，走的是既有链路。批量视图里每行可各选一篇，不特殊处理。

## 边界

`markdown()` 的输出仍逐段转义：md 里写 `<script>` 只会显示成文字。KaTeX 自动渲染默认跳过 `pre`/`code`，代码块里的 `$` 不会被当公式。

## 验收

`python -m pytest tests -q` 全绿；浏览器实测：模板下拉出现「使用文档」，参数区只有「文档」下拉，切文档右侧即时换页；导出 HTML 与离线版（661 KB）结构、样式齐全。
