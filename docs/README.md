# 文档索引

Probatrix 的文档按**读者**分五处，改文档前先确认它属于哪一层——混写是把文档写坏的头号原因。

| 位置 | 读者 | 这里写什么 | 什么时候要动 |
|---|---|---|---|
| [架构全景.md](架构全景.md) | 开发者 | 系统怎么运转：入口、数据流、跨子系统约定、边界 | 机制或契约变了 |
| [subsystems/](subsystems/) | 开发者 | 单个子系统的规范（界面、计算书排版…） | 该子系统的实现变了 |
| [cookbook/](cookbook/) | 开发者 | 操作步骤：起环境、跑测试、打包发布 | 工具链变了 |
| [postmortem/](postmortem/) | 开发者 | 事故复盘：现象、根因、防复发 | 出了事故 |
| [manual/](manual/) | **用户** | 安装、界面操作、写模板——**随便携包分发** | 用户看得见的行为变了 |

`manual/` 是唯一会被 `tools/build_release.py` 拷进便携包的目录，其余目录不进发行物。

写作规矩（完整准则见仓库根 `AGENTS.md`）：

- 不写「以前 / 现在 / 不再」这类历史变迁——那是一次性的故事，不是文档。
- 不手抄 API 列表——真源是 `src/probatrix/__init__.py` 和 `tests/` 里的契约测试。
- 「为什么这么定」不进这里，进 `.agents/notes/`（决策记录，写完即冻结）。
