# 架构全景

Probatrix 是结构小构件的批量计算与计算书生成工具：模板作者用 Python 写验算逻辑，计算人员在表单或表格里输入参数，计算书由模板直接生成 HTML + LaTeX，导出后即可打印。

> 速查数据流见仓库根 `AGENTS.md`；本文是展开版，补充入口形态、跨子系统约定与边界。

## 1. 两种入口，同一套后端

| 入口 | 启动方式 | 界面载体 |
|---|---|---|
| Windows 便携包 | 解压后双击 `Probatrix.exe`（Tauri 宿主） | WebView2 加载本机回环端口的 Vue 界面 |
| pip 安装 | `probatrix serve --templates <目录>` | 浏览器打开 `http://127.0.0.1:8317` |

两条路径跑同一个 FastAPI 应用（`src/probatrix/server.py`），托管同一份前端构建产物（`src/probatrix/web/`）。

桌面形态下，Tauri 宿主以无控制台方式启动 `probatrix.desktop`；Python 监听就绪后回报本机端口，宿主据此加载页面。页面与 `/api` 同源，单件与批量计算复用同一个 Python 进程。窗口操作（拖动、缩放、关闭）限定给主 WebView 与本次回环地址；关窗关闭 stdin 管道，通知 Python 正常停机。

## 2. 一条声明，三处跟随

模板作者在 Pydantic `Field` 上声明一次元信息（`label / unit / choices / group / batch_hidden / row / show_if`），下游三处自动跟随：

- 单件表单的控件类型、分组、并排布局、条件显隐（`SingleView`）
- 批量表格的列、默认显隐、统一设置的分组（`BatchView`）
- `.pbproj` 里每行的参数 JSON

**改参数契约要三处一起考虑**，否则会出现「表单能填、表格不显示」这类不一致。

## 3. 计算与渲染

```
模板 .py ──loader──▶ meta（id、hash、params schema、deps 检查）
        ──engine──▶ run_template：校验 → 执行 → 永不抛异常
                    失败时 traceback 原样进 RunResult.error（这是模板作者的调试界面）
        ──Builder─▶ items ──to_html()──▶ HTML（LaTeX 交给 KaTeX）
```

- 管线是 **items → HTML 直通**，中间没有 Markdown 解析层。结构只由 Builder API 决定，文本一律转义后进入行内格式处理（只认 `**粗体**`）。
- `check()` 是一等公民：正文输出判定行 + 文末自动汇总「验算结论」表 + 暴露 `max_ratio` 供批量表格标红。
- `metric(name, 值)` 只进批量表格的结果列，不进正文。
- `to_markdown()` 是纯导出物（供人下载阅读），不参与界面渲染。

## 4. 工程文件

`.pbproj` 是纯 JSON：`items[{id, name, template_id, template_hash, params, deps}]` + `views`，写入 `format_version: 1`，版本不符直接报错（不做旧版回退）。

参数在每行始终存完整值——「统一设置」是批量赋值操作，不是存储结构，因此没有隐藏状态。

`hash` 只覆盖模板主文件；`deps` 为依赖模块预留，当前不计入 hash。

## 5. 交付物

| 产物 | 内容 | 由谁产出 |
|---|---|---|
| wheel | 含 `src/probatrix/web`（前端构建产物）与 `src/probatrix/vendor`（KaTeX），使用侧无需 Node | `npm run build` + `pip wheel` |
| 便携 ZIP | `Probatrix.exe`、内嵌 Python 3.12 + 常用计算库、`examples/`、`docs/manual/` | `tools/build_release.py` |

`src/probatrix/web` 与 `src/probatrix/vendor` 是**提交入库的构建产物**，不要手改。

## 7. 边界（刻意不做）

参数联动与派生（选型号自动带截面特性）、Word 导出、依赖模块 hash、模板库集中分发、CSV/Excel 文件导入、自动单位引擎。

模板内部统一使用 SI 基本单位，`Field(unit=...)` 只负责界面展示——不做自动换算引擎，只立规矩。

这些取舍的理由记在 [.agents/notes/2026-09-05-计算书工具设计定稿.md](../.agents/notes/2026-09-05-计算书工具设计定稿.md)。
